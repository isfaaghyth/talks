1. Introduction & Architecture Overview

⏱️ Estimated time: 5 mins • Level: Intermediate

Welcome to the hands-on codelab for An agentic workflow for autonomous engineering loops for Android. In this workshop, we move beyond basic LLM code-completion / chat tabs and build a fully automated, self-hosted agentic engineering loop tailored for Android developers using pang.

💡 What is an Agentic Workflow?
An agentic workflow is not just asking an LLM to generate a snippet. It is a long-running, state-aware system where an orchestrator agent monitors human intentions (e.g. notes), spawns isolated builder agents, invokes real compiler/CLI tools (like Gradle & ADB), tests output, and reports results back via chat.

Core Concept & Terminology Deep Dives

To master architecting mobile agentic workflows, understand these key components:

01. Dynamic Agent Pattern

Ephemeral Builder Subagent

Proper Terminology: Ephemeral Per-Project Builder Subagent. Rather than keeping a single bloated agent, hermes-agent provisions temporary subagents (e.g. eng-timerapp) per build. This prevents context bloat, prompt drift, and file conflicts.

02. Headless Project Seeding

scaffold (`scaffold.sh`)

Generates baseline Android Jetpack Compose code with AGP 8.7, Kotlin 2.0, compileSdk 35, and Gradle wrapper without Android Studio UI, consuming Google Stitch UI design tokens.

03. Event Trigger Engine

project-tick (`project-tick.py`)

A 60s cron polling watcher registered via hermes cron in --no-agent mode. Scans Markdown note YAML frontmatter for status: backlog → in-progress with state debouncing.

04. Artifact Delivery Pipeline

deliver (`deliver.sh`)

The post-build script that validates generated app-debug.apk binaries and ships them to Telegram as documents or directly onto devices over adb connect Wi-Fi.

3. Setting Up the Cognitive Core (Obsidian Vault)

⏱️ Estimated time: 8 mins • Vault Architecture

The Cognitive Core is a plain Markdown Obsidian vault stored locally at ~/ippang/vault-project/. Agents interact with Markdown notes as human-readable, vendor-agnostic long-term memory.

Vault File Structure

directory structure 
~/ippang/vault-project/
├── _templates/
│   ├── 00-context.md          # Project specification & status
│   ├── 10-architecture.md     # Architecture decisions
│   └── 20-task-log.md         # Agent execution trail
└── timerapp/
    └── 00-context.md          # The active note watched by cron

The `00-context.md` Specification Note

Every mobile project starts as a note with structured YAML frontmatter:

~/ippang/vault-project/timerapp/00-context.md 
---
project: timerapp
instance: ippang
platform: mobile
status: backlog # backlog -> in-progress triggers the builder agent!
created: 2026-08-18T10:00:00+0700
---

# TimerApp Specification

Build a clean Jetpack Compose countdown timer app for Android.
- Features: Start, Pause, Reset, audio alarm tick notification.
- UI: Modern dark theme with Space Grotesk font styling and clean progress ring.
⚠️ Instance Tagging Guard
Notice instance: ippang in frontmatter. This isolation guard prevents other personal agents from accidentally picking up engineering projects.

4. The Trigger Mechanism (`project-tick.py`)

⏱️ Estimated time: 7 mins • Event Engine

Instead of exposing HTTP webhooks or open ports, pang uses project-tick.py — a periodic watcher registered with hermes cron that scans the Obsidian vault every 60 seconds.

How `project-tick.py` Operates

_instance/hermes-cron/project-tick.py 
import os, glob, yaml

TERMINAL_STATES = ["completed", "failed", "error"]

for note_path in glob.glob("vault-project/*/00-context.md"):
    with open(note_path) as f:
        fm = yaml.safe_load(f.read().split("---")[1])

    # 1. Instance isolation check
    if fm.get("instance") != "ippang":
        continue

    # 2. State transition check: backlog -> in-progress
    if fm.get("status") == "in-progress" and not is_dispatched(fm["project"]):
        mark_dispatched(fm["project"])
        spawn_orchestrator(fm["project"], brief=note_path)

    # 3. Terminal status report to Telegram
    if fm.get("status") in TERMINAL_STATES:
        print(f"[{fm['project']}] Build status: {fm['status']}")

Registering the Hermes Cron Job

terminal 
hermes cron create '* * * * *' --no-agent \
    --script project-tick.py --deliver telegram --name ippang-projects
🛡️ Debouncing State
The tick engine uses state hashes so modifying note body prose will never re-trigger a build. Only explicitly editing status: backlog → in-progress fires the build loop!

7. Production Guardrails & Subagent Isolation

⏱️ Estimated time: 5 mins • Safety & Quality

Autonomous code generation requires strict guardrails to protect security, stability, and code quality.

The 3 Pillars of Safety in `pang`

01. Verification

Automated Testing

Build subagents must execute unit tests (./gradlew testDebugUnitTest) before declaring build success.

02. Review Pipeline

PR & Human Review

Subagents commit to feature branches and open Pull Requests. Automatic PR checkers enforce code review before merge.

03. Security

API Key Sandboxing

LLM credentials live solely inside KeiRouter. Agents never hold raw API keys or private signing keys.

⚠️ Isolation Rule
Each project build runs under its own subagent (eng-timerapp, eng-counterapp). Never allow multiple projects to share a single agent workspace context!
