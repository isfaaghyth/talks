03 / 18 COMPARE

Same bug, two ways to close the loop

Scenario: a Kotlin Multiplatform build is red. Who does the looping — you, or the agent?

Normal Prompt

You are the loop.
you ask for a fix
you paste the build error
you apply the suggested patch
you rebuild, see it's still red
Repeat manually, from the top, each time it fails.

Loop Engineering

The agent is the loop.
you state the goal once
agent runs the build, reads the error
agent edits the code, rebuilds
agent repeats — until green
You reappear once, to review the opened PR.
04 / 18 TOOLING

The stack behind the loop

Agent core

hermes-agent

Runs the plan → act → observe loop for every agent.

Obsidian

A synced vault agents read and write as shared memory.

keirouter

Routes each agent's model calls by cost and capability.

Ecosystem & ops

Basecamp

The shared queue agents pick work from.

Sentry

Error monitoring across mobile and backend.

Supabase

The database the backend agent reads and writes.

Firebase

Auth, crash reporting, and remote config for the app.

Bitrise

CI that builds, signs, and ships the app.

GitHub

Where every agent's loop ends — an opened PR.

09 / 18 THE GHIATH REPO

What ghiath actually is

An open skeleton repo — a ready-made scaffold that wires agent profiles, predefined skills, shared memory, and an LLM gateway into one place you can point at your own project.

# conceptual layout — swap for your real folder names ghiath/ ├─ agents/ # mobile-dev, frontend-dev, backend-dev profiles ├─ skills/ # /new-project, /kmp-build, /open-pr-loop, /self-improve ├─ memory/ # Obsidian vault adapter — the cognitive core ├─ gateway/ # keirouter config — model routing └─ hermes.config # orchestration entry point
10 / 18 VALIDATION FIRST

Why validate with web before mobile

Mobile builds, tests, and distribution are expensive — so the frontend-dev agent proves an idea on web first, cheaply, before mobile-dev commits to it.

Expensive

Mobile round-trip

Build → device test → Bitrise CI → store review. Every loop costs real minutes.

Cheap

Web round-trip

Edit → hot reload → click through. A loop that costs seconds.

Validate the flow and UX on web, then hand the confirmed design to mobile-dev.

12 / 18 COGNITIVE CORE

Memory has three layers

You ask a question or hand off a task
Obsidian — the vault holding notes on this
CouchDB syncs that vault to every agent
Qdrant finds the most relevant notes — semantic, not keyword, search
Agent uses that context to act on your task
↺ what the agent learns gets written back to Obsidian, ready for next time.

14 / 18 ADD-ON AUTOMATION

n8n — automation when reasoning isn't needed

Needs reasoning

hermes-agent

  • Fix a failing build
  • Review and revise code
  • Plan out a new feature
No reasoning needed

n8n

  • Nightly vault backup
  • Notify Telegram when a PR merges
  • Sync a Basecamp ticket's status

n8n sits beside the agent stack for plumbing that's deterministic, not decision-making.

18 / 18 CONCLUSION

The workflow is the product, not the prompt

  • An agent alone is just a smarter autocomplete — the loop is what makes it useful.
  • Shared memory, scoped agents, and reusable skills turn one-off prompting into a repeatable system.
  • Start small: one agent, one skill, one worktree — then let the pipeline grow.
